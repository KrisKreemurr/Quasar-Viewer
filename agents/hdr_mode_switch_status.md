## Source findings

- `indra/newview/vkgfx/llvulkancontext.cpp:2424-2454` snapshots the active mode, recreates WSI, prepares/destroys HDR targets, and retires the entire format-specialized `LLCleanRendererVK`. `VkSwapchain::recreate()` currently drains with `vkDeviceWaitIdle()` (`vkgfx/vk_swapchain.cpp:282-287`), but the context had no explicit output-generation/replay state. The old code only cleared `mWorldInitTried` inside the `mWorld != nullptr` branch; a failed replacement could leave a null renderer permanently marked as already attempted.
- The owner confirms the transition also crushes avatars before they disappear. The root is two-part: singleton `AvState.seeded`/`topo_slot` outlive renderer-owned local-pose/topology buffers, and the replacement has no populated skin palette until its first rigged recording. Stale format-specialized color pipelines can also produce incorrectly dark avatar shading if the new mode draws before its required pipeline batch is ready. The reset API clears consumer seed/topology/follow markers and old readback records, then forces topology and arena publication. The new renderer's `buildRiggedFrame()` runs at the start of `recordWorld()`; its animation dispatch, joint table, and skin-palette work are recorded before rigged draws in that same command buffer. `doWorld` now waits for the required world pipeline gate in SDR and HDR, and still waits for the generation's full store sync, so a replacement generation does not draw through old/incomplete format pipelines. Deferred optional RT pipelines remain outside that gate.
- Before deleting the drained renderer, `preserveCompletedAnimationReadbacks()` consumes completed sparse rings and makes one temporary transfer copy of the bounded `mAnimLocal` buffer (at most `MAX_AVATARS * 216 * 48` bytes). The copy has an explicit compute-storage-write to transfer-read dependency, then transfer-write to host-read dependency. Valid seeded slots restore their complete local pose into `AvState.seed` and current LL joints. Component base-write bits 1/2/4 and `GPU_EXT_DIRTY` keep newer CPU transforms authoritative; additive bit 8 does not suppress copying the GPU pose. If `mAnimHeld` contains a prepared but undispatched frame, its per-avatar base-write records are parsed and those joints retain their current CPU locals in the reseed. Allocation is soft-fail and staging is freed immediately. If unavailable, mode switch falls back to the existing CPU pose plus sparse readbacks. This is best effort, not a fidelity guarantee after staging refusal or for unseeded slots. A held prepared frame is not replayed byte-for-byte: its current base writes are recovered, and the next live avatar update rebuilds the active motion export. Do not claim that every prepared one-shot blend program survives. The new renderer also has per-instance animation-buffer clearing; the prior process-static clear flag skipped zeroing newly allocated local/joint buffers after renderer replacement. The `llcleananimstore.cpp` API insertion is separate from Copernicus's joint-delta edits in that file; coordinate the merge and preserve both.
- Confirmed incomplete-output hazard: `recordWorld()` reports `displayOutputComplete()`, but the old context logged that HDR was incomplete and still encoded the target as `CompleteDisplay` (`llvulkancontext.cpp`, former lines 2803-2820). The renderer's final path can report incomplete when the required final pass is unavailable (`llcleanrenderervk.cpp:44968`). Its intermediate is relative linear, whereas the display encoder consumes absolute nits; encoding it as complete output explains black/dark world output during a pipeline/target gap.
- Parent clarified that a fresh SDR launch is correct; the report that SDR remained washed out after toggling was retracted. No exposure policy or exposure-history change is made. The facade paper-white value is reset to its SDR default on a committed HDR-to-SDR transition as mode-state cleanup, not as an asserted cause of the brightness report.

## Implemented transaction

- Mode changes are committed as a new display generation after WSI recreation/drain and HDR target preparation. A mode mismatch without a prior WSI recreation explicitly drains before resource replacement. World retirement and init state are invalidated even if the prior renderer pointer is already null.
- A fresh renderer must finish the normal `syncFromStores()` pass before its display generation is eligible to draw. That pass replays the fresh instance/geometry/material/skin-meta mirrors within the existing store and renderer caps; dynamic lights, shadows, animation, palettes, rigged draw lists, and impostor work then run through their normal per-frame inputs before the first world draw. The new renderer owns fresh world targets, exposure image/history, pipelines and descriptors; these are not copied from the retired generation.
- Both SDR and HDR world drawing wait on `worldPipelinesPending()` for the replacement generation. Its existing contract includes required first-use geometry/color/post/final pipeline work and excludes deferred optional ray-query variants. In HDR, while that gate is active, the initialized HDR clear and UI may be presented; no relative-linear world intermediate is passed to the absolute encoder.
- If composition or the final transfer still reports incomplete (for example a refused target allocation or failed pipeline), the context refuses to encode the partial scene, writes a valid encoded fallback background, and requests a drained fail-closed SDR recreation. A failed renderer initialization is retried with a two-second backoff; transitions reset that backoff.
